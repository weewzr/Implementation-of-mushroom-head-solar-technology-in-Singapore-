# Full Master-Instruction Audit Template

Every mandatory three-turn audit must review **all 15 sections** of `docs/MASTER_INSTRUCTIONS.md`, not merely a short quality checklist. For each section record **PASS / PARTIAL / FAIL / NOT YET APPLICABLE**, evidence, deficiencies, and corrective action.

## 1. Canonical project objective
Check Singapore land constraint, 3-D PV geometry, mushroom origin, broadened geometry search, and falsifiability/no presumed winner.

## 2. Required deliverables
Check Markdown, LaTeX, PDF, derivations, nomenclature, reproducible code, plots, diagrams, tables/renders, provenance, bibliography, README/roadmap, and tests.

## 3. Foundation material
Check `docs/foundation/` was consulted for any scope/objective/terminology/baseline/optimisation change; preserve mushroom/sphere/topology/momentum lineage.

## 4. Three-turn audit cadence
Count turns since previous audit. Audit no later than turn 3. Record substantive audit in `docs/audits/`.

## 5. Mathematical rendering / definitions / constants
Check every important equation renders; every symbol is defined immediately with units; every non-trivial number is classified and justified; category 2/3 values have authoritative citations; assumptions have rationale/sensitivity; numerical settings have convergence consequences; dimensions/limits/sign conventions are checked; Markdown/LaTeX/PDF math is valid.

## 6. Logic and exposition
Check physical problem, coordinates, assumptions, stepwise derivation, coefficients, variables/units, dimensional/limiting checks, physical interpretation, and implementation explanation for important equations.

## 7. Visualisation and human-centred design
Check every major phase has visuals; semantic colour system; colour-blind/greyscale accessibility; quantitative visuals derive from code/data; conceptual visuals are labelled; captions state assumptions/provenance/status; required visual families are progressing.

## 8. Evidence and provenance
Check separation of verified facts, sourced measurements, assumptions, exploratory calculations, generated results and hypotheses; authoritative Singapore/primary sources preferred; redistribution rights respected.

## 9. Reproducibility
Check code regenerates tables/figures; assumptions/constants/provenance/units recorded; sanity tests exist; no hand-edited numerical result.

## 10. Required baselines
Check horizontal fixed, optimised fixed tilt, east-west/folded, vertical bifacial where relevant, single-axis, dual-axis, conventional canopy, sphere/hemisphere, cone, paraboloidal mushroom, faceted/sparse canopy and eventual free-form topology optimisation under equal resources.

## 11. Core optimisation philosophy
Check footprint efficiency versus module/material efficiency; packing ratio and land multiplication; packing gains weighed against orientation, shading, sky-view, temperature, structure, cost and maintenance; best fixed geometry before tracking.

## 12. Mechanical interpretation
Check original momentum question preserved but not misinterpreted as maximizing angular momentum; analyse inertia, counterbalance, friction, actuator energy, aerodynamic centre, wind torque, locking and storm stow.

## 13. GitHub workflow / permissions
Check proactive canonical-repository use where access exists; meaningful commits; foundation separated from validated conclusions; never claim platform security/auth can be bypassed.

## 14. Public-repository discipline
Check no credentials, private personal information, restricted/proprietary datasets or unlicensed redistributed material.

## 15. Quality gate
Before any milestone: equations/units/constants verified; tests run; figures/tables regenerated; LaTeX/PDF compiled; pages/math/figures visually inspected; references verified; assumptions/limitations labelled; foundation intent retained.

## Mandatory audit conclusion
List all FAIL/PARTIAL items in priority order. Correct blocking deficiencies before major new modelling. Explicitly state whether the project may proceed to the next scientific phase.
